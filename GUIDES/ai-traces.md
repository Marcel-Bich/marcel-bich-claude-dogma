# AI Traces Guide

<typography>
## Typography - Avoiding AI-Typical Characters

Certain punctuation characters reveal AI-generated content. Always replace the characters listed below with their plain ASCII equivalents.

**Scope:** This ASCII replacement applies ONLY to the punctuation characters in the table below (curly quotes, smart apostrophes, em-dash, en-dash, ellipsis). It does NOT apply to letters. German umlauts follow the opposite rule - see the umlauts section below.

| Avoid | Unicode | Use Instead | Unicode |
|-------|---------|-------------|---------|
| " " | U+201C, U+201D (curly quotes) | " | U+0022 (straight quote) |
| ' ' | U+2018, U+2019 (smart apostrophes) | ' | U+0027 (straight apostrophe) |
| ‚ | U+201A (low-9 quote) | ' | U+0027 |
| -- | U+2014 (em-dash) | - | U+002D |
| -- | U+2013 (en-dash) | - | U+002D |
| ... | U+2026 (ellipsis) | ... | Three dots |

**Double-dash rule:** `--` is ONLY allowed when changing it to `-` would break functionality. Examples:
- Allowed: `--force`, `--recursive`, `-r` (CLI flags - function requires it)
- Allowed: `git checkout -- file`, `runuser -- \` (argument separator - function requires it)
- NOT allowed: `# this is important -- do not skip` (comment - no functional purpose)
- NOT allowed: `echo "Loading -- please wait"` (string - no functional purpose)
- NOT allowed: `# gh wrapper -- auto-switch` (comment - just a text separator)

**In short:** if `--` has no functional meaning (nothing breaks when replaced with `-`), always use `-`. Applies to prose, documentation, comments (including code comments) and strings.

**Why these matter:**
- AI models often produce these Unicode characters
- Human typing typically produces ASCII equivalents
- Presence of these characters can indicate AI-generated content
</typography>

<umlauts>
## German Umlauts - the Opposite Direction

The ASCII rule above is about punctuation. For German letters the rule is REVERSED.

German umlauts (ä ö ü ß) are mandatory in German prose, comments, docs, UI strings and error messages. Dropping them - writing ae/oe/ue/ss instead - is ITSELF an AI trace: AI habitually omits umlauts, so their absence is the telltale sign, exactly like curly quotes or em-dashes. Real umlauts are the human-correct form, not a trace.

- German prose / comments / docs / UI / error messages -> real ä ö ü ß are REQUIRED.
- ae/oe/ue/ss as a replacement for an umlaut = AI trace = forbidden (same category as curly quotes).
- **Exception:** identifiers (variables, functions, filenames, classes, DB columns, API paths, git branches) stay ASCII, where ae/oe/ue/ss is correct and not a trace.

See language.md for the full context boundary.
</umlauts>

<markers>
## Handoff and AI-Author Markers

Never leave markers that reveal AI authorship or an AI/human handoff in versioned or shipped content (code, comments, docs).

**Banned - handoff placeholders left open for a human:**
- `TODO(human)`, "your code here", "implement here", empty placeholder slots

**Banned - AI-author phrases:**
- "AI-generated", "written by Claude", "generated by AI", "as an AI"

**Allowed:** ordinary task-related `TODO` / `FIXME` that a human would genuinely write. The ban targets only markers that expose AI involvement or an AI/human split, not normal work notes.
</markers>

<phrases>
## AI-Typical Phrases

Avoid these patterns in comments and documentation:

| Avoid | Why |
|-------|-----|
| "Let me..." | AI assistant pattern |
| "I'll..." | AI assistant pattern |
| "Sure!" | Overly eager response |
| "Certainly!" | Formal AI response |
| "Great question!" | Unnecessary validation |
| "I'd be happy to..." | AI politeness pattern |

**Better alternatives:**
- Just do the thing without announcing it
- Use direct, factual language
- Skip pleasantries in code comments
</phrases>

<emojis>
## Emojis in Code

**Never use emojis in:**
- Source code
- Comments
- Variable/function names
- Log messages
- Error messages

**Allowed in:**
- UI strings (user-facing output)
- Documentation (sparingly)
- Commit messages (if project convention)

**Rationale:** Emojis in code are unprofessional and often indicate AI generation.
</emojis>

<detection>
## Detection

The dogma `post-write-validate` hook automatically checks for these patterns after Write/Edit operations and warns if found.

**Manual check with grep:**
```bash
# Curly quotes (U+201C, U+201D)
grep -P '[\x{201C}\x{201D}]' file

# Smart apostrophes (U+2018, U+2019, U+201A)
grep -P '[\x{2018}\x{2019}\x{201A}]' file

# Em-dash and en-dash (U+2014, U+2013)
grep -P '[\x{2014}\x{2013}]' file

# Ellipsis (U+2026)
grep -P '[\x{2026}]' file

# Handoff / AI-author markers
grep -nE 'TODO\(human\)|your code here|implement here|AI-generated|written by Claude|generated by AI' file
```

**Cleanup command:**
```bash
/dogma:cleanup
```
</detection>
